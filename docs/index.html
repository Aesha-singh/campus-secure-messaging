CSCP: a protocol designed, not borrowed

Every message is a length-delimited binary frame, so TCP's byte stream is cut back into messages reliably, with integrity checked on every frame.

Message types

Hello, auth, direct and group messages, ACK, typing, presence, sync, read marks, file offer, chunk, resume, ping and error frames.

Replay and DoS guards

Sequence numbers reject replayed frames, and a hard frame-size limit protects the server from memory exhaustion.

Fuzzed and tested

Framing, partial reads, malformed and oversized frames are covered by codec and fuzz tests.

Defense in depth

Three layers between a message and an eavesdropper

LAYER 1 · TRANSPORT

TLS 1.3 with mutual auth

A local CA signs the server and client certificates. Clients pin the server certificate, so a man-in-the-middle with a forged cert is rejected.

LAYER 2 · IDENTITY

Argon2id and TOTP

Salted Argon2id password hashes, time-based 2FA, token-bucket rate limiting and lockout against brute force.

LAYER 3 · END TO END

X25519 → HKDF → AES-GCM

Keys are agreed between devices and pinned out of band (TOFU). The server stores and relays ciphertext only.

The full STRIDE threat model is written up in the repository under docs/threat_model.md.

Features

Built like a real service

Store and forward

Offline messages persist in SQLite (WAL) and replay on reconnect, with unread badges and history sync.

Reliable delivery

ACK correlation and msg_id de-duplication turn at-least-once delivery into effectively-once.

File relay

Encrypted chunked transfer with a sliding window, resume from a byte offset, per-user quotas and TTL cleanup.

Desktop client

PyQt6 with qasync, so one event loop owns both the socket and the widgets. Shows live transport status.

Admin endpoint

A hand-rolled HTTP/1.1 listener on its own port serves JSON metrics and a health check.

Deployable

Docker, docker-compose and a hardened systemd unit, with production TLS config and secret handling.
